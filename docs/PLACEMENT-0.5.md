# Placement, inventory and orders in 0.5

The game's sheet tutorial explicitly permits drag/drop at a chosen position or a click that automatically finds a position. Native controller placement previously gave the keyboard user that automatic position. In the inspected sheet, the paper rectangle was 632.16 by 894 canvas units with a centred pivot; the automatically placed first copy was near its top-left at X -238.22, Y 390.02. These are layout units, not centimetres or screen pixels. Positive X goes right; positive Y goes up.

Keyboard Enter still calls the native PrintedStickerElement drag/controller creation and drop methods, then moves that real copy to the paper rectangle centre or the packing collider's centre. The placement is not a separate accessible simulation. Sheet validity, inventory, package membership and tutorial callbacks remain native. Mouse handlers are not patched to recenter their placements. New copies can overlap at the centre; the player chooses where to move them and the game's validity rules still apply.

Arrows move the chosen copy, Shift uses larger steps, Q/E invoke the native rotation, Delete removes that copy and Tab/Enter ends adjustment. Position speech gives a region and percentages measured from the area's left and top edges; it describes the copy's pivot, not its entire outline. Values outside 0–100 indicate the pivot is outside the area. C reads canvas-unit offsets from that same area's centre, where X 0/Y 0 is centred. Native overlap/inside-box feedback accompanies the position.

Inventory is available in the inspected tutorial production step. It begins open and shows the chosen design with available/ordered counts (0/19 in the fixture). The native ToggleInventory opens or hides that sidebar; it is not an inventory-management screen transition. The mod now announces the actual open/closed state and rows on opening. F4 then Up/Down reads the rows individually. Tutorial dialogues can still legitimately cover or disable controls.

Sighted players see incoming customer names/messages on the hub's order board. Order packing (hub shortcut 5) shows a phone with the current customer/message and required sticker thumbnails/remaining quantities. Previous/next arrows change the real current order; a displayed value and deadline accompany it. O reads the displayed order and F4/Up/Down reads its sections. The coin balance appears at the bottom-left of gameplay beside a coin icon. B reads that actual visible text, which is also included in F4 information. Order value is distinct from current balance.

Packing paper/filling selection compares the actual rendered sprite AND colour with each native option; packing tab selection reads PackingExtrasManager.extrasState. Actions such as Add sticker, Add goodie and Pack are momentary actions, not selected/unselected choices. No new order, extra printed inventory, artificial completion or payment is created by these accessibility changes.

Settings slider adjustment/repeat, text edit review/deletion, category selection and category scrolling are preserved. Optional goodie positioning still needs separate work; the centered arrow-adjustment workflow covers printed sticker copies.
