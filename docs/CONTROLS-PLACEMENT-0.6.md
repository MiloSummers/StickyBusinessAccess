# Controls and placement update 0.6

The native Controls setting chooses Mouse/controller input. Actual UI inspection and generated input classes did not show an existing player action-rebinding menu. Accessibility controls therefore extend the existing Settings canvas with a separate native-style page; the original input-mode dropdown and sliders are untouched. The page shows all 45 accessibility actions (including alternates), current keys, paging, restore defaults and Back. Bindings save in the mod’s BepInEx config. Duplicate accessibility keys are rejected; matching bindings in the game’s controller, mouse and UI input assets warn and require confirmation. Windows/NVDA modifier keys are reserved. Single-key bindings only. Text editing retains ordinary native keys, independently of remapped navigation.

Border Width uses `BorderColorChanger.GetPixelBorderSize()`, the actual shader width, in pixels. Runtime activation changed 4 to 5 and speech reflected that value. No visual numeric slider was invented. The clock tutorial’s English clock instruction adds the current time-reading key once in that instruction. Routine screen announcements and inventory reads omit function-key prompts; the README is the full default shortcut reference, with contextual help still available on demand.

Delete now handles a focused placed element/copy as well as adjustment mode, through native destruction/undo or inventory-return actions. The first copy on an empty sheet/box starts centred. Later sheet copies use randomized points within the real sheet; later packing copies keep native random placement. No design or order is chosen for the player. Held movement repeats, accelerating after 0.75 seconds; Shift uses larger steps immediately. Position speech is throttled to roughly twice a second and reports the final value on release.

Printing uses actual native collider contacts, checked after a physics settling delay. Its stripped IL2CPP build lacks polygon-distance queries; rectangle overlap is deliberately avoided because transparent corners can have overlapping bounds without overlapping sticker shapes. Invalid new drops are removed, and invalid moves/rotations revert. Overlap feedback identifies another sticker when the contact contains a printed copy. The native area membership also prevents final outside-area positions. Packing permits native stacking and uses the real box/inventory callbacks. These restrictions apply to keyboard copy placement; mouse handlers retain their original game behaviour. Creative Corner elements may intentionally overlap to form a design.

## Verification scope

The project builds without warnings/errors and its 24 existing automated checks pass. Isolated tests confirmed actual sheet/box centres, randomized later copy positions, focused-item deletion, returned packing inventory, periodic held-movement speech, accelerated movement (75 canvas units in a two-second hold), actual polygon-contact overlap blocking with return to the previous valid position, an intentionally overlapping private fixture visibly tinted invalid with Save disabled, the Settings controls page’s visible labels, duplicate-key rejection, binding capture/cancel, and time binding persistence across restart. F10 read the native game time after rebinding T in the private config. No user save was loaded or overwritten by the fixture. Private test code and save redirection are excluded from the normal release.

Physical keyboard timing, audible NVDA speech/interruptions, live text-field regression and all rebind combinations need user testing. Native conflict matching (including wildcard paths), the final once-per-hold blocked feedback and narrower clock-only tutorial hint were build-checked after the runtime tests. Optional packing goodies are not yet equivalent to printed-copy positioning. Twitch linking remains unverified. Test with a separate shop; native actions retain their ordinary effects.
